# I. Тесты MVP (Фаза 1 — Процесс «Принятие автомобиля в работу»)

В данном разделе приведены тест-кейсы для проверки базовой функциональности MVP (UC-1 ... UC-4).

---

## 1.1 Тест-кейсы для UC-1. Зарегистрировать клиента и авто

### 1.1.1 Задача
* **Задача:** [TASK-01. Разработать интерфейс и логику регистрации клиента и автомобиля](task-1.md#task-01-uc-1)

### 1.1.2 Основной сценарий (Позитивный)
| Шаг | Описание шага | Ожидаемый результат |
|---|---|---|
| **1** | Открыть форму «Регистрация клиентов и авто» в АРМ Менеджера | Пользователь видит форму с полями поиска и кнопкой «Добавить клиента» |
| **2** | Ввести корректный номер телефона (`+7 999 123-45-67`) или VIN | Система выполняет поиск и выводит сообщение: «Записи не найдены» |
| **3** | Нажать кнопку «Зарегистрировать нового клиента» | Открывается форма ввода персональных данных клиента и автомобиля |
| **4** | Заполнить ФИО, телефон, e-mail и корректные данные авто (Марка, Модель, VIN 17 символов, Госномер) | Пользователь видит заполненную форму без ошибок валидации |
| **5** | Нажать кнопку «Сохранить» | 1. Отображается уведомление «Клиент и авто успешно зарегистрированы».<br>2. Присваиваются `КлиентID` и `АвтоID`.<br>3. Выполняется переход в карточку клиента. |

### 1.1.3 Негативный сценарий (Невалидный VIN / Телефон)
| Шаг | Описание шага | Ожидаемый результат |
|---|---|---|
| **1** | Открыть форму регистрации нового клиента и авто | Пользователь видит пустую форму ввода |
| **2** | Заполнить ФИО и ввести некорректный VIN (меньше 17 символов, например `XTA2110001234`) | Пользователь видит заполненные поля |
| **3** | Нажать кнопку «Сохранить» | 1. Выводится сообщение об ошибке: «Некорректный формат VIN-кода (должно быть 17 символов)».<br>2. Поле VIN подсвечивается красным цветом.<br>3. Сохранение блокируется. |
| **4** | Закрыть уведомление об ошибке | Пользователь остается на форме регистрации |
| **5** | Скорректировать VIN до валидного 17-значного значения | Подсветка ошибки исчезает |
| **6** | Нажать кнопку «Сохранить» | Выполняется успешное сохранение и переход в карточку клиента |

## 1.2 Тест-кейсы для UC-2. Создать заказ-наряд

### 1.2.1 Задача
* **Задача:** [TASK-02. Разработать модуль инициализации и создания заказ-наряда](task-1.md#task-02-uc-2)

### 1.2.2 Основной сценарий (Позитивный)
| Шаг | Описание шага | Ожидаемый результат |
|---|---|---|
| **1** | Выбрать зарегистрированный автомобиль в АРМ Менеджера и нажать «Создать заказ-наряд» | Открывается экран создания нового заказ-наряда |
| **2** | Заполнить текстовое поле «Причина обращения / Жалобы клиента» (например, «Стук в передней подвеске») | Пользователь видит заполненное поле причины обращения |
| **3** | Нажать кнопку «Сформировать заказ-наряд» | 1. Создается документ заказ-наряда.<br>2. Присваивается уникальный номер и статус **«Черновик»**.<br>3. Автоматически подтягиваются данные клиента и автомобиля. |

### 1.2.3 Исключительный сценарий (У автомобиля есть открытый заказ-наряд)
* **Предусловия:** В системе зарегистрирован автомобиль (VIN: `XTA21100012345678`), для которого уже создан и не закрыт заказ-наряд №101 в статусе «В работе».
* **Тестовые данные:** Автомобиль VIN `XTA21100012345678`, `АвтоID`: 42.

| Шаг | Описание шага | Ожидаемый результат |
|---|---|---|
| **1** | В АРМ Менеджера найти автомобиль VIN `XTA21100012345678` и открыть его карточку | Отображается карточка автомобиля и список его заказов, включая активный заказ-наряд №101 |
| **2** | Нажать кнопку «Создать заказ-наряд» | 1. Выводится модальное окно с предупреждением: «Создание невозможно: для автомобиля уже открыт заказ-наряд №101 в статусе "В работе"».<br>2. Кнопка подтверждения создания заблокирована. |
| **3** | Нажать кнопку «Перейти к открытому заказ-наряду» | Выполняется переход в карточку существующего заказ-наряда №101 |

## 1.3 Тест-кейсы для UC-3. Добавить работы и запчасти

### 1.3.1 Задача
* **Задача:** [TASK-03. Разработать интерфейс калькуляции работ и расходных материалов](task-1.md#task-03-uc-3)

### 1.3.2 Основной сценарий (Позитивный)
| Шаг | Описание шага | Ожидаемый результат |
|---|---|---|
| **1** | Открыть заказ-наряд в статусе «Черновик» и перейти во вкладку «Калькуляция» | Отображается пустая таблица сметы и строки поиска |
| **2** | Найти и добавить услугу из справочника работ (например, «Замена передних амортизаторов») | Работа добавляется в смету, отображается цена и норма-часы |
| **3** | Найти деталь в справочнике запчастей, проверить наличие на локальном складе и добавить в заказ | Система подтверждает наличие детали на локальном складе СТО и добавляет позицию |
| **4** | Нажать кнопку «Пересчитать смету» | Система корректно рассчитывает итоговую сумму сметы с точностью `Decimal(10,4)` |

### 1.3.3 Негативный сценарий (Деталь отсутствует на локальном складе)
| Шаг | Описание шага | Ожидаемый результат |
|---|---|---|
| **1** | В калькуляции заказ-наряда ввести артикул детали, отсутствующей на локальном складе СТО (остаток = 0) | Система выводит всплывающее предупреждение: «Деталь отсутствует на локальном складе СТО» |
| **2** | Нажать кнопку «Подобрать аналог» | Отображается список совместимых аналогов, имеющихся на локальном складе |
| **3** | Выбрать доступный аналог и нажать «Заменить» | Позиция успешно заменяется в смете, сумма пересчитывается |

## 1.4 Тест-кейсы для UC-4. Принять автомобиль в работу

### 1.4.1 Задача
* **Задача:** [TASK-04. Реализовать функционал назначения ресурсов и перевода заказ-наряда в статус «В работе»](task-1.md#task-04-uc-4)

### 1.4.2 Основной сценарий (Позитивный)
| Шаг | Описание шага | Ожидаемый результат |
|---|---|---|
| **1** | В согласованном заказ-наряде нажать кнопку «Принять в работу» | Открывается модальное окно назначения ресурсов |
| **2** | Из выпадающего списка «Мастер» выбрать доступного сотрудника | Имя мастера зафиксировано в форме |
| **3** | Из выпадающего списка «Бокс/Пост СТО» выбрать свободный бокс (например, «Бокс №2 (Подъемник)») | Бокс зафиксирован в форме |
| **4** | Нажать кнопку «Подтвердить приемку» | 1. Статус заказ-наряда меняется на **«В работе»**.<br>2. Фиксируются точные дата и время приемки.<br>3. Заказ-наряд появляется в рабочем столе выбранного Мастера. |

### 1.4.3 Негативный сценарий (Попытка назначения на занятый бокс)
| Шаг | Описание шага | Ожидаемый результат |
|---|---|---|
| **1** | В форме приемки выбрать свободного Мастера и указать Бокс, в котором уже выполняется другой ремонт | Пользователь видит выбранный бокс |
| **2** | Нажать кнопку «Подтвердить приемку» | Выводится ошибка: «Бокс №1 занят до 16:00 заказ-нарядом #1042. Выберите другой бокс». |
| **3** | Выбрать из списка свободный Бокс №3 | Ошибка скрывается |
| **4** | Нажать «Подтвердить приемку» | Заказ-наряд успешно переводится в статус «В работе» |
