# II. Тесты первого релиза (Фаза 2 — Заказ запчастей и интеграции)

В данном разделе приведены тест-кейсы для функциональности Первого релиза (Заказ недостающих запчастей и складские интеграции).

## 2.1 Тест-кейсы для UC-REL-2. Оформить заказ недостающей запчасти

### 2.1.1 Задача
* **Задача:** [TASK-REL-01. Разработать модуль оформления заявки на закупку недостающих запчастей](task-2.md#task-rel-01-uc-rel-2)

### 2.1.2 Основной сценарий (Позитивный)
| Шаг | Описание шага | Ожидаемый результат |
|---|---|---|
| **1** | При добавлении запчасти в смету зафиксировать отсутствие остатка на локальном складе и нажать «Оформить заказ поставщику» | Открывается модальное окно формирования заявки на закупку |
| **2** | Указать количество и согласовать с клиентом увеличенный срок поставки | Пользователь видит заполненные параметры заказа |
| **3** | Нажать кнопку «Сформировать заявку» | 1. Создается заявка на закупку со статусом «Ожидает отправки».<br>2. Заявка автоматически связывается с ID текущего заказ-наряда.<br>3. Заказ-наряд переходит в статус «Ожидание запчастей». |

### 2.1.3 Негативный сценарий (Отказ поставщика / Таймаут API)
| Шаг | Описание шага | Ожидаемый результат |
|---|---|---|
| **1** | Отправить заявку на закупку детали внешнему поставщику при недоступности API поставщика | Выполняется попытка отправки запроса |
| **2** | Дождаться ответа системы по истечении таймаута (10 сек) | Выводится уведомление: «Ошибка связи с поставщиком. Заявка сохранена локально со статусом Ошибка отправки». |
| **3** | Нажать кнопку «Повторить отправку» после восстановления связи | Заявка успешно передается поставщику, статус меняется на «Заказано». |
