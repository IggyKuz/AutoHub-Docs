# II. Тесты первого релиза (Фаза 2 — Заказ запчастей и складские интеграции)

В данном разделе приведены тест-кейсы для функциональности Первого релиза (Проверка остатков на ЦС, внутренние перемещения и заказ недостающих запчастей у внешних поставщиков).

---

## 2.1 Тест-кейсы для UC-REL-1. Проверить наличие и зарезервировать запчасть на центральном складе

### 2.1.1 Задача
* **Задача:** [TASK-REL-00. Разработать интеграцию проверки остатков и резервирования на Центральном складе (ЦС)](task-2.md#task-rel-01-uc-rel-1)

### 2.1.2 Основной сценарий (Позитивный)
* **Предусловия:** Запчасть отсутствует на локальном складе текущей СТО (`StockBalance = 0`), но в наличии на Центральном складе (ЦС) имеется достаточное количество. Заказ-наряд находится в работе.
* **Тестовые данные:** Запчасть: `Амортизатор передний (Артикул: AM-01)`, Остаток на ЦС: `4 шт.`.

| Шаг | Описание шага | Ожидаемый результат |
|---|---|---|
| **1** | В калькуляции заказ-наряда добавить запчасть `AM-01` | Система фиксирует отсутствие позиции на локальном складе СТО и инициирует проверку на Центральном складе (ЦС) |
| **2** | Система отображает доступность детали на ЦС и предлагает сформировать резерв | Пользователь видит информацию о наличии на ЦС и срок перемещения |
| **3** | Нажать кнопку «Зарезервировать с ЦС» | 1. Система резервирует необходимое количество деталей на Центральном складе.<br>2. Автоматически формируется документ внутреннего перемещения с ЦС на склад СТО назначения.<br>3. В сметке заказ-наряда фиксируется статус позиции «Зарезервировано на ЦС». |

## 2.2 Тест-кейсы для UC-REL-2. Оформить заказ недостающей запчасти у внешнего поставщика

### 2.2.1 Задача
* **Задача:** [TASK-REL-01. Разработать модуль оформления заявки на закупку недостающих запчастей через внешние API](task-2.md#task-rel-01-uc-rel-2)

### 2.2.2 Основной сценарий (Позитивный)
* **Предусловия:** Требуемая запчасть отсутствует как на локальном складе СТО, так и на Центральном складе (ЦС). Настроено активное соединение с внешними поставщиками по API.
* **Тестовые данные:** Запчасть: `Ступичный подшипник (Артикул: PART-999)`, Внешний поставщик: `ООО «АвтоПрайс» (API)`.

| Шаг | Описание шага | Ожидаемый результат |
|---|---|---|
| **1** | При добавлении запчасти `PART-999` в смету система подтверждает отсутствие остатков на локальном складе и ЦС | В интерфейсе калькуляции активируется кнопка «Запросить у внешних поставщиков» |
| **2** | Нажать кнопку «Запросить у внешних поставщиков» | Система отправляет автоматический запрос API / прайс-листы внешних поставщиков |
| **3** | Выбрать оптимальное предложение по цене и сроку доставки из списка и нажать «Оформить заказ поставщику» | Открывается модальное окно формирования заявки на закупку |
| **4** | Указать требуемое количество и нажать кнопку «Сформировать заявку» | 1. Создается заявка на закупку со статусом «Ожидает отправки».<br>2. Заявка автоматически связывается с ID текущего заказ-наряда.<br>3. Заказ-наряд переходит в статус **«Ожидание запчастей»**. |

### 2.2.3 Негативный сценарий (Отказ поставщика / Таймаут API)
* **Предусловия:** Запчасть отсутствует на локальном складе и ЦС. Сервер внешнего поставщика временно недоступен (обрыв сети / превышение таймаута).
* **Тестовые данные:** Запчасть: `PART-999`, Таймаут ожидания API: `10 секунд`.

| Шаг | Описание шага | Ожидаемый результат |
|---|---|---|
| **1** | Сформировать заявку на закупку детали внешнему поставщику при недоступности API | Выполняется попытка отправки запроса внешнему поставщику |
| **2** | Дождаться ответа системы по истечении таймаута (10 сек) | Выводится уведомление: «Ошибка связи с поставщиком. Заявка сохранена локально со статусом Ошибка отправки». |
| **3** | Нажать кнопку «Повторить отправку» после восстановления связи с поставщиком | Заявка успешно передается поставщику, статус заявки меняется на «Заказано». |
